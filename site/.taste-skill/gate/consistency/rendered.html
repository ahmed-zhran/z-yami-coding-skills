Release, spec, and ticket bases. The open checkout is never the destination.

01 · Release

Release branch

release/<N> cuts from main. It holds every feature of the cycle. The version tag lands on the merge into main. 

main
 └─ release/1
     ├─ spec/42
     └─ ticket/55-hotfix

02 · Spec

Spec branch

spec/<issue> is one feature. It lands into the open release. The level lives in the name; the parent lives in the base. 

release/1
 └─ spec/42-lineage
     ├─ ticket/42-cli
     └─ ticket/42-docs

03 · Ticket

Ticket branch

ticket/<issue>-<slug> is one tracer path. It lands into its spec. A bug lands into the open release, a hotfix, or main. 

spec/42-lineage
 └─ ticket/42-cli
    PR → recorded base

Three ship doors, one land gate. Higher doors land everything beneath them.

/ship-ticket

Ticket ship door

You approve the ticket merge. One issue, one worktree, one PR into the recorded base.

/ship-ticket
→ PR open
→ you land

/ship-spec

Spec ship door

The session lands every ticket. You approve only the spec PR into its base.

/ship-spec
→ tickets land
→ you land spec

/ship-release

Release ship door

The session lands tickets and specs. You approve only the release PR into main.

/ship-release
→ specs land
→ you land release

Parent steer keeps every pane working.

You stay where you typed the ship command. The parent clears allowlist dialogs and packs child panes.

Screen loop

Allowlist dialogs

Cursor often leaves status as working while a dialog waits. The parent polls the screen and clears each with a run-once y. 

ticket-10 · working
Run this command?
  npm test
[y] once · Approval 1 of 1
→ cleared · working again

Child tabs

Six-pane Herdr grid

The shipping tab stays alone. Children pack into sibling tabs, close after land, and never steal focus from the parent.
