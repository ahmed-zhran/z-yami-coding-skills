How work lands

              

                Work climbs from a lower-level ticket into a higher-level spec/<issue>,
                then into release/<N>, and finally onto main.
                The checked-out branch is never the base — each level lands into the one above it.
              

              

                The ship door you typed owns that level’s land gate; everything below lands under that session’s authority.
                You approve only the gate that belongs to the door you opened.
              

            

            

              
Requirements

              

                Claude Code, Codex, or another agent that skills.sh can install into
                (Cursor, OpenCode, Windsurf, Devin, Amp, Pi).

Orchestration · ship-release

          
One release prompt. Specs, tickets, and parallel children.

          

            /ship-release plans the release, cuts dependent specs and tickets, then spans child agents on independent work while blocked tickets wait.
            Results fold back to the main agent — dependency-aware shipping, not a flat todo list.

Issue types

          
Three issue kinds. Ticket issues carry the subtypes.

          

            Every issue is a release, a spec, or a ticket. Ticket issues go further: feature/tracer, bug, research, or hotfix — each with a recorded **Base:**, surfaces, blockers, and what it delivers.

Branch lineage

          
Every branch records a base. The chain is the heartbeat.

          

            Work never assumes main. Each ticket, spec, release, and hotfix records the branch it was cut from and lands back into.
            The checked-out branch is never the base — following those base links upward is the lineage.

                  01
                  

                    
Resolve & record **Base:**

                    
Issue body is canonical. Git config mirrors it as branch.<name>.base. Never invent a base from whatever is checked out.

                  

                

                

                  02
                  

                    
Cut work in a worktree

                    
Create the branch from the base tip, isolate it in a worktree, and keep the recorded base attached before any commit lands.

                  

                

                

                  03
                  

                    
Land, then restack children

                    
Merge into the recorded base through the ship door that owns that level. Open children move onto the landed branch’s own base and retarget their PRs.

                  

                

              


              

                

                  Safe land gates
                  PRs open into the recorded base — never accidental merges into main.
                

                

                  Stacked work
                  Children can depend on unlanded tickets without losing the climb back to main.
                

                

                  Restack after land
                  When a base lands, dependents rebase onto the new base and keep moving.
                

                

                  One truth, two mirrors
                  Issue **Base:** wins; git config mirrors it for tools that never open the tracker.
                

              

            

          

        

      

    


    

      

        

          
Code gating

          
Tests, review, PR — then the door that owns the land.

          

            Work does not skip the rail. TDD seams and typecheck come first; code-review runs Standards and Spec axes before the pull request; landing only happens through the ship door that owns that level — and the release PR into main stays human.
          

        


        

          

            Gate rail
            idle · waiting for viewport
          

          

            

              01
              
TDD seams

              
Red specs first. Implement against observable behaviour, not source intuition.

            

            

              02
              
Typecheck

              
Package and workspace types stay green before review and before the PR opens.

            

            

              03
              
code-review

              
Standards + Spec by default. Security on risky diffs. Deep when you ask.

            

            

              04
              
Pull request

              
pr opens into the recorded base with evidence from review and CI.

            

            

              05
              
Ship-door land

              
/ship-ticket, /ship-spec, or /ship-release owns that level’s land gate.

            

            

              06
              
Human → main

              
Only the release PR into main is the human land gate for a full release.

            

          

        

      

    


    

      

        

          
Writing limits · agents & humans

          
Leave constraints to work with agents and humans.

          

            Shipping is not only code. Handoffs, questionnaires, agent-facing docs, and debt notes keep the limits that future departments — and future agents — need when they pick the work up.
          

        


        

          

            Handoff surface
            idle · waiting for viewport
          

          

            

              
handoff + questionnaires

              
Bridge between prototype and shaping, and capture decisions humans still own. to-questionnaire turns open questions into a durable form other teams can answer later without replaying the chat.

            

            

              
unslop before humans read it

              
Changelog sections, release notes, and PR bodies get a de-slop pass so filler and AI tells do not ship to other departments as the official record.

            

            

              
writing-for-agents

              
Skills and AGENTS.md use context pointers, progressive disclosure, and trigger wording so later agents load the right constraints instead of guessing from chat history.

            

            

              
shortcut: → /debt

              
Temporary escapes stay marked in source. Post-release, /debt harvests them into a ledger and issues so other teams inherit the limit instead of rediscovering the shortcut.

Review axes

            
Standards and Spec on the diff by default. Security on risky diffs. Deep when you ask for a strict maintainability pass.

          

          

            
Surfaces

            
A map of each app, service, and package, the contracts between them, and the context an agent needs in a monorepo.

          

          

            
Bugs

            
A bug ticket lands into the open release, a hotfix cut from the production tag, or main when no release is open.

          

          

            
Learning loop

            
Solution notes after non-obvious fixes, a debt ledger and retro after the tag, plus a skill evaluator for triggers.
